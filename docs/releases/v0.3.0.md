# agent-project v0.3.0

**Released 2026-11-16. A minor release.** Since [v0.2.0](v0.2.0.md): bus back-pressure (a task is claimed only when a worker is free, with a per-customer limit), the licence, the security policy, base images pinned by digest and the public-tree cleanup. Image: `docker.io/oramasearch/agent-project:v0.3.0`, not published (see *Known issues*).

This release is the tree of `dev` with these notes and the version.

### A bus task is claimed only when a worker is free — #41

- Every received task used to be claimed and queued, so one tenant's burst held claimed tasks (with their credentials) in memory and starved the others (#33).
- `lake_bus.work` now claims only when a worker slot is free and receives nothing while all are busy. `AGENT_BUS_WORKERS` (default 4) sets the slots and `AGENT_BUS_TENANT_WORKERS` (default one fewer) caps one customer; at most 256 dispatch rows wait. `receive` passes the long poll's `wait_ms`.
- Both settings are optional; their defaults apply when unset, so no operator change has to roll first.

### The public-tree cleanup — #45

Nothing internal is left in the files that will be published: `.public-exclude` was added and then removed again once the agent files were rewritten to ship publicly; issue links became plain text, the image section shows a `docker buildx build` with the two named contexts, the release notes name no environment, and the package author is `Orama Search Inc.`.

### The licence — #46

Everything in this repository that Orama wrote is under the MIT licence. Contributors sign `CLA.md` once. `THIRD_PARTY_LICENSES` lists every runtime dependency with its licence text; none is incompatible with MIT distribution.

## Before it rolls: the settings it needs

Nothing required. `AGENT_BUS_WORKERS` and `AGENT_BUS_TENANT_WORKERS` (#41) are optional, with defaults. The other variables are unchanged from [v0.2.0](v0.2.0.md).

## Known issues

Security-relevant first. All open at this tag.

1. #47 (release blocker for publishing): the image is built on `python:3.12-slim`, which bundles GPL and LGPL userland, so **the image is not published**. It is built and kept in the project's non-public Docker Hub repository until it moves to a scratch base with static binaries.
2. #34: turn traces keep workspace content on the pod's disk (`TRACE_DIR`), outside the workspace Zetta.
3. #17: the task's workspace is not passed explicitly on data-plane calls and delegated turns. Lake scopes the task credential to the task's workspace.
4. #28: the analysis fallback does not read `get_dataset`'s typed columns.
5. #27: designing does not detect class imbalance or report imbalanced runs by PR-AUC and lift.
6. The catalogue build context is produced outside this repository; a public user needs a published catalogue to build the image.

## Where it has run

**The v0.3.0 tree had not run on a development environment when it was released.** Lakes run the operator's default image of this agent; the changes since v0.2.0 are proven by the test suite only. Moving a Lake to `:v0.3.0` is a separate operator change.

## The image

Built from the tag `v0.3.0` with BuildKit (linux/amd64, the repository's Dockerfile) after the tag is pushed; the digest is recorded here by a follow-up change. It is pushed only to the project's non-public Docker Hub repository.
